# 亚马逊经营分析项目复刻操作手册

本手册对应交付包中的八页 Power BI 项目。先跑通现成项目、确认基准数字，再从空白报表重建数据、模型和页面；每完成一层就检查一次，避免最后面对一整页错误却找不到原因。

数据是为本项目构建的业务模拟数据，用于复刻与学习；不需要亚马逊账号。报表标题保持正常业务名称。项目采用美国站、美元、2025 年第四季度、18 个 SKU 的业务场景。

## 1. 你需要准备什么

- Windows 电脑、支持 PBIP/PBIR 的 Power BI Desktop。原项目截图来自 2.158.1304.0，其他版本界面可能不同。
- 完整解压的项目文件夹，建议放在固定目录，例如 `D:/PowerBI/amazon-business-powerbi`。
- Python 3：用于自动配置路径和检查数据，不需要安装第三方库。也可以手工配置路径，但数据检查脚本仍需要 Python。
- 为手工重建另建一个工作文件，例如 `我的经营分析.pbix`；不要覆盖参考项目。

项目入口是 `amazon-business.pbip`。`Amazon.Report` 保存页面，`Amazon.SemanticModel` 保存模型，`data` 保存 15 张 CSV。三者必须一起保留。不要直接双击压缩包中的入口文件。

微软说明：[Power BI 项目文件](https://learn.microsoft.com/power-bi/developer/projects/projects-overview)。如果文件类型无法打开，先核对 Desktop 版本及“选项 → 预览功能”中项目格式相关设置；按本机提示启用并重启。不要使用针对 Report Server 优化的 Desktop 来复刻 PBIP。

## 2. 路线一：先打开现成项目

1. 解压后，在项目根目录的空白处右键，打开终端。确认当前目录能看到 `amazon-business.pbip`。
2. 执行以下命令。若系统使用 `py` 启动 Python，可把 `python` 换成 `py`。

```powershell
python scripts/configure_paths.py
python scripts/check_data.py
```

3. 第一个脚本把 `__DATA_DIR__` 改为本机数据目录；第二个检查数据对账。两者没有报错后，用 Desktop 打开入口并刷新。
4. 在经营总览选择 2025-12，款式、颜色、尺码清空选择，核对第 9 节数字。
5. 保存。以后整个文件夹搬家，先关闭 Desktop，重新运行路径脚本，再打开刷新；外部修改模型时不要同时在 Desktop 保存旧版本。

手工替代方法：关闭 Desktop，打开 `Amazon.SemanticModel/model.bim`，仅把所有 `__DATA_DIR__` 替换为 data 文件夹路径，使用正斜杠，保留 CSV 文件名。不要改其他 JSON 内容。

**检查点：** 八个页面可以打开、刷新没有错误、总览基准数字一致。达到这一步，才开始手工重建。

## 3. 路线二：从空白报表导入数据

1. 新建空白报表，进入“主页 → 转换数据”。
2. 按[附录二](附录二_查询与关系.md)逐一创建空白查询，粘贴对应完整代码，并替换数据路径。查询名称必须与附录完全一致。
3. 每次检查预览：首行应为字段名，日期列应为日期，SKU 保持文本，件数与点击为整数，金额为数值。
4. 建好 14 个查询后“关闭并应用”。其中 12 个读取 CSV，两个利润辅助表由代码生成；不是把 15 个 CSV 全部重复导入。
5. 在数据视图抽查日期和商品：日期不能重复、商品 SKU 不能重复。原始订单、补货和仓储费用文件保留在数据包中用于追溯，最终模型不直接加载它们。

[数据字典](DATA_DICTIONARY.md)列出各文件字段与行数。流量是日期与 SKU 粒度；广告还包含活动、关键词与匹配方式；退货与财务是事件明细；库存是每日 SKU 快照；目标是月份与 SKU 粒度。不能把这些表直接拼成一张宽表后对金额求和。

**检查点：** 查询无错误，类型正确，14 张模型表全部出现。若 CSV 已有正确首行，只提升一次标题，不能把第一条业务记录提升成列名。

## 4. 建立模型关系

进入模型视图，按附录二建立 20 条关系。日期和商品在“一”端，各事实表在“多”端，筛选方向设为单向，保持活动。若自动检测创建了事实表之间的关系，逐一核对并移除不属于清单的关系。

选择日期表，使用“表工具 → 标记为日期表”，指定日期列。图表使用 `日期[日期]` 本身，不要误选自动日期层次结构。月份切片器使用 `日期[年月]`，年月文本采用 YYYY-MM 格式，可以按升序排列。

利润辅助表不连关系。财务科目的筛选由利润度量负责。去年同期表的关系键是映射到当前期间的“日期”，不能换成“同期日期”。目标表的日期是月初，只用年月切片器控制月度目标。

**检查点：** 临时放一个商品 SKU 表格和销量度量，选择一个款式后只有该款式 SKU 留下；选择一个月份后销量随之变化。关系规则可参考[微软模型关系说明](https://learn.microsoft.com/en-us/power-bi/desktop-create-and-manage-relationships)。

## 5. 创建指标，而不是计算列

在日期表上右键“新建度量值”，按[附录一](附录一_全部度量值.md)顺序逐个粘贴。每个代码块是一条完整公式，不能一次粘贴多条。附录保留最终模型的 101 个度量值，并把依赖项排在前面。

先完成销售额、订单数、销量、商品会话数、订单会话比、客单价等基础指标，用卡片检查，再继续利润、库存、广告、退货、同比和目标指标。保存时保留中文名称，后续图表才能对应字段配置。

必须理解的口径如下：

| 指标 | 本项目含义 |
|---|---|
| 销售额 | 折扣后的订购销售额，未减后续退款 |
| 订单会话比 | 总订单数 ÷ 总商品会话数，不是逐行百分比平均 |
| 客单价 / 件均售价 | 销售额 ÷ 订单数 / 销售额 ÷ 销量 |
| 经营贡献利润 | 财务表带正负号金额合计，不等同完整公司净利润 |
| 利润率 | 经营贡献利润 ÷ 折扣前销售收入；不要擅自改成销售额分母 |
| 环比 | 当前自然月与上一个自然月比较，保留商品筛选 |
| 库存覆盖天数 | 期末可售库存 ÷ 近 7 天日均销量 |
| 库存周转天数 | 平均库存成本与销售净成本计算，与覆盖天数不同 |
| 搜索词出单率 | 有订单的搜索词数 ÷ 有点击的搜索词数，按搜索词文本去重 |

订单会话比的环比是相对变化率，不是百分点。例如 3.68% 对比约 3.56%，相对增加约 3.2%，不等于增加 3.2 个百分点。只选一个月时看环比；首月没有上月数据时显示说明，不能强填为 0%。

广告页“活动＋关键词零订单花费”按活动和关键词组合判断；搜索词页可能存在零订单且有花费的搜索词，因此两者不能直接要求相等。固定 10 天退货率按订单观察窗口计算，与按退货发生日期统计的当月退货件数不是同一个分子。

更多生成假设见[指标口径](METRICS.md)。**检查点：** 基础指标能按月份、商品正确筛选，除法使用汇总分子与分母，空值没有被无条件替换为 0。

## 6. 制作统一页面骨架

1. 画布设为自定义 1440 × 900，页面视图选择适合页面。
2. “视图 → 主题 → 浏览主题”导入根目录 `theme.json`。预览截图存在不同阶段的配色，以交付主题为复刻起点。
3. 添加年月、款式、颜色、尺码四个下拉切片器；年月来自日期表，其余来自商品表。打开切片器标题，使用清楚的中文名称。
4. 左侧筛选区宽约 162；主要内容从 x=186 开始。先建一页骨架，再复制页面并替换内容。
5. 卡片显示单位设为“无”，件数与订单数为整数；金额表格保留两位，百分比通常一到两位。关闭重复的类别标签，保留明确标题。
6. 表格关闭自动列宽后拖动列边界；金额右对齐、文字左对齐，保留总计。避免为了塞入所有列把字号压得过小。

每个图的准确坐标、类型和字段槽均在[附录三](附录三_八页字段配置.md)，按页面从上到下重建即可。编辑模式看到的点状网格属于对齐辅助，不要据此额外制作一张点状背景。

## 7. 八页应该怎样制作

| 页面 | 制作顺序与重点 |
|---|---|
| 经营总览 | 五个核心卡片及各自环比 → 每日销售柱图和转化趋势 → 广告与利润、总订单与广告订单 → 款式销售 → SKU 明细；左侧补件均售价和同比 |
| 利润分析 | 四张卡片 → 三级利润矩阵 → 所选科目金额和收入占比趋势 → 款式利润表 |
| 流量分析 | 四张卡片 → 自然与广告来源会话 → 款式订单会话比 → 总订单与自然订单、客单价 → SKU 明细 |
| 库存管理 | 四张卡片 → SKU 库存表 → 款式、颜色、尺码汇总 → 缺货、预留、周转和无销量库存卡片 |
| 广告分析 | 四张效率卡片 → 花费和归因销售趋势、关键词成本比 → 五张曝光点击卡片 → 活动关键词表 |
| 退货分析 | 四张卡片 → 按原因分组的每日退货折线、原因分布 → 商品明细和原因金额表 → 10 天观察指标 |
| 目标管理 | 四组实际值、目标值、完成率 → 款式实际与目标对比 → SKU 月度执行表 |
| 搜索词明细 | 四张汇总卡片 → 活动、关键词、搜索词、点击、订单、花费、销售额、成本比明细 |

### 利润矩阵的关键操作

插入矩阵，在行中依次放一级项目、二级项目、三级科目；列放年月；值放选中利润项目金额、选中项目收入占比。打开加减号，逐级展开。不要同时把旧版“利润表行”混入此矩阵。

选中矩阵，进入“格式 → 编辑交互”，把右侧两张趋势图设为“筛选”，再点一个费用科目观察结果。金额应跟着变为该科目，费用可能为负数；取消选中后返回整体经营贡献利润。展开层级和选择科目是两种操作，展开本身不会必然筛选趋势。

### 库存与目标的关键操作

库存表使用期末度量，不对每天快照直接求和。近 7/14/30 天以所选期间末日向前计算；不足窗口的历史不能当成完整窗口。状态可显示彩色圆点及文字；如需条件颜色，使用“库存状态颜色”度量作为字段值。无销量卡片使用“30天无销量库存显示”，区分 0、历史不足和无库存数据。

目标页先选单月。销量卡片与销量目标为整数；广告预算使用率不是利润完成率。目标状态依照项目既有公式判断销售额完成情况，不要误解为所有经营目标同时达成。

**检查点：** 逐页对照[预览图](PREVIEW.md)。截图筛选条件不同，必须先匹配月份、款式、颜色和尺码再比数字；不能把不同筛选下的卡片差异判为错误。

## 8. 设置并检查联动

选择一个切片器后进入编辑交互，确认它对本页业务图表是“筛选”。如果你希望切换页面仍保留同一筛选，在“视图 → 同步切片器”逐页勾选同步；如果要复现截图中各页独立选值，则不要强制同步。同步状态和是否在页面显示是两个独立选项。

依次测试月份 → 款式 → 颜色 → 尺码。选择到单 SKU 后，明细只剩对应 SKU，卡片应等于该行指标；取消筛选后恢复总计。单击柱形会额外产生交叉筛选或突出显示，核对总计前先点击空白取消选择。

对利润页单独测试三级科目筛选；对目标页测试 SKU 与月份共同筛选；对库存页测试不同月份的期末值。操作参考[微软切片器说明](https://learn.microsoft.com/en-us/power-bi/visuals/power-bi-visualization-slicers)。

## 10. 常见问题怎样排查

| 现象 | 优先检查与处理 |
|---|---|
| 找不到 CSV | 是否完整解压；路径是否仍为占位符；搬家后重跑路径配置 |
| 查询循环引用 | 在高级编辑器检查当前查询是否引用自己；日期错误可阻断多个查询，不能只根据最后一个报错表定位 |
| 缺少分号或 M 语法错误 | 对比附录完整 M 代码；不要盲目补分号。模型中的表达式可能是字符串或行列表，错误地逐字符拆分也会破坏查询 |
| 卡片空白 | 先清空所有筛选；再查关系、日期和数据范围。除数为0或窗口历史不足可能应当留空 |
| 销售额被放大 | 查重复 SKU、多对多、双向关系、事实表直接连接，以及是否把原始订单再叠加导入 |
| 月环比不对 | 确认只选一个自然月，日期完整且商品筛选保留；不要用前等长天数替代上月 |
| 利润率和销售额除不一致 | 项目利润率用折扣前销售收入作分母，查看指标口径后再判断 |
| 目标筛选一天后空白 | 目标是月初记录，按月份使用，不能与日粒度目标混淆 |
| 图表与明细不一致 | 取消图表点选，检查视觉级筛选、交互设置、显示单位及度量绑定 |
| 计数出现 .0 | 模型格式与卡片格式分别检查，小数位设为0 |

## 11. 如何换成自己的数据

先保留一份能通过验收的项目，再逐表替换。保持同名字段和同一粒度；商品、日期必须覆盖全部业务记录。退货观察表、流量来源、去年同期、搜索词和目标属于独立输入，不能仅替换销售表就声称整套模型已更新。

更新顺序：确定字段映射与口径 → 更新相关 CSV → 修改查询类型或字段映射 → 检查关系 → 刷新 → 用你自己的原始汇总重新对账。新日期超出第四季度时，应同步扩展日期表及所有需要覆盖的辅助数据。

此包是固定快照，不包含自动生成全部衍生数据的程序、Amazon API 接入或自动定时刷新。复刻现有项目可以直接使用提供的数据；生产接入需另行建立数据更新流程。

## 12. 学习顺序与交付保存

建议每次只完成一个可验收成果：第一次跑通现成项目；第二次重建查询和关系；第三次做经营总览；第四次完成利润与库存；第五次完成其余五页；最后统一联动、格式和对账。每个阶段另存一份可打开的版本。

最终保存项目入口、Report、SemanticModel、data 和文档。对外分享前关闭 Desktop，检查本地路径与缓存；只分享整理后的压缩包，不附账号信息。项目可以上传 GitHub，但当前交付仅是仓库文件与压缩包，并不代表已经创建远程仓库。
